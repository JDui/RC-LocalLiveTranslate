# 效率维护：有界字幕与分段存储

本轮保留 Hy-MT2 STQ、识别、拾音、声纹和翻译队列容量。目标是消除会话时间越长、历史记录越多时的内存累积和主线程大 JSON 工作。单句模型计算耗时仍需另行按 `21_TRANSLATION_SPEED_PLAN.md` 验证。

## 内存与写入边界

| 路径 | 边界 | 满载行为 |
| --- | --- | --- |
| 实时字幕 | 最近 500 条，快照缓存；迟到结果不扩充实时窗口 | 旧字幕移出屏幕，在启用记录时仍保存于数据库；页面显示限制提示 |
| 记录事件 | IO worker，Channel 128 | 挂起推理发布者，AudioRecord 不等待磁盘；已有音频队列继续执行既定积压策略 |
| 批量持久化 | 每批最多 32 条命令，或首次命令后 250 ms；仅写变更行 | 停止时排空；存储失败明确停止采集并提示，保留已成功写入的记录 |
| 记录 worker 缓存 | 500 行；未来翻译/提前说话人结果各最多 256 项 | 淘汰缓存，旧段修订从数据库取单行；未知下游事件不创建空字幕 |
| 列表查询 | 每页 50 条元数据，不读取全文 JSON | 只在记录页订阅，前后翻页 |
| 详情与导出 | 每页 200 条；导出使用索引游标流式写入 | 详情只观察当前页的数据库变更，前后翻页；导出完整会话，不拼接全量字符串 |
| 翻译队列 | 8 条，仅保留文本、语言、段标识及修订号 | 原有积压提示和未翻译状态不变；不再因等待翻译保留 PCM |

RealtimePipeline 先提交 journal，再更新实时快照。事件按 sessionId / segmentId 和各自 revision 处理；完整记录支持实时窗口以外的译文与说话人修订。说话人合并先写别名，再通过 SQL 修改历史行，正文和翻译修订不变。缓存和别名不持有 embedding 或音频。

## Room v1 → v2

新增 `session_captions` 表，主键为 `(sessionId, segmentId)`，查询索引为 `(sessionId, startSample, segmentId)`，删除会话级联删除字幕。新记录只在 `sessions` 保留元数据；`captionsJson` 保留为 `[]` 以兼容旧字段和旧记录。

升级数据库只增加表和索引，不在启动时解析全文。第一次查看或导出旧记录时，在 IO 上以 SQLite `substr` 每次读取 16,384 个 Unicode 码点、JsonReader 逐对象解析，每 100 行 upsert。避免 Android CursorWindow 一次装入巨大 blob。解析完成才清空旧 JSON；解析失败或中途退出保留原文，可重试，不通过删除数据库处理迁移错误。旧记录的缺失目标语言 / 修订字段继续采用旧默认值。SQL 码点偏移与 Java UTF-16 Reader 偏移分别维护，避免非 BMP 字符边界错位。

## 隐私与停止

关闭保留设置时，先同步关闭保留意图并增加独立代次，再写 DataStore。待写事件带入队时的代次；IO worker 检查代次和门禁，清除当前未结束记录及缓存。独立代次流能唤醒空闲 worker，快速重新开启也不能重放关闭前的待写内容；已结束记录不自动删除。关闭期间识别和实时字幕照常工作，重新启用只保存之后收到的新记录事件。

录音停止先等待 pipeline 退出，再排空记录 worker，更新时长并脱离 journal；Room、编码和导出均在 IO。演示保存也检查入队代次和事务后的保留意图。当前正在写入的记录不能手动删除，页面提示先停止会话，避免后续事件重新创建已删除的会话。

## 缓存与日志检查

PCM 环形缓存固定 160,000 float 样本，推理各队列有界；声纹证据最多 256 个向量、生命周期最多 16 个标签。Hy context 为固定 token 上限，每段清理 KV，handle 复用并在结束后释放。RunDiagnostics 每阶段耗时最多 2,048 项，硬件样本最多 720 项，每 5 秒采样，不包含对话或音频；仅显式导出才写文件。没有追加生产文件日志、自动诊断落盘或遥测。原生 llama 日志回调仍关闭，sherpa 的 debug 默认关闭。

这些边界阻止应用自身的缓存随时长无上限增长，不等同于不存在任何 native 内存问题。完整记录会按保留意图占用磁盘；本轮不自动删除已有记录。Room 级联删除是逻辑删除，不承诺文件缩小或物理擦除。存储不足会触发保存错误；闪存写入量、native 峰值、翻译速度和 30–60 分钟持续运行需要 ARM64 真机验证。

验证结果见 `11_VALIDATION.md`。
